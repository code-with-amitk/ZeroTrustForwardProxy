== Data-plane read & AST build
=== Validations
- Opens policy.db read-only, reads policy_meta and verifies schema_version
- queries rules, unmarshals JSON fields, then calls buildAST

=== Benefits of reading db inplace of json
- 1. Lower peak memory: JSON parse creates a whole nested structure; SQLite reads deserialize per-row, reducing temporary allocations and GC pressure.
```
**Read Json Flow**
1. Open file and read entire JSON(5000 rules) into memory.
2. Unmarshal whole JSON into nested structs/maps
3. Iterate rules, extract fields, compile regex patterns into in-memory regex objects.
4. Build AST (index rules by type and priority), then drop raw JSON object (garbage-collected).

**Reading db**
1. Open SQLite file
2. Run a query like `SELECT ... FROM rules ORDER BY policy_type, priority, id` to stream rows already ordered.
3. Build AST
```
- 2. Faster load for large rules: DB can stream rows in the desired order and relies on optimized C/SQLite IO. JSON parsing of a big document is single-threaded and can be slower.
- 3. OS-level caching: SQLite uses the OS page cache and WAL optimizations (PRAGMA journal_mode=WAL used by compiler), often giving better IO behavior than repeatedly parsing JSON files.
